# CLAUDE.md

Guide for Claude Code (and anyone else) working in this repository.

## What this is

Varad Patel's personal site, published with GitHub Pages.

| | |
|---|---|
| Home page | https://varad-patel.github.io |
| 365 gallery | https://varad-patel.github.io/365projects/ |
| This repo | https://github.com/varad-patel/varad-patel.github.io (the `main` branch is what is served) |
| The projects' code | https://github.com/NotNeverMe/365D365P (separate repo: Python, Streamlit, tests, data caches) |

Static HTML, CSS and vanilla JavaScript. No build step, no framework, no bundler. Pushing to `main` runs the tests
(`pytest`) and a Pages deploy that takes about a minute.

## Commands

```bash
python -m pytest -q                       # must pass before every push
python -m http.server 8000                # preview at http://localhost:8000 (the gallery is /365projects/)
python scripts/build_data.py              # after changing anything under data/
```

### Add a project that was just built in the projects repo

Clone the projects repo next to this one as `../365-projects` (or pass `--repo`), then from this repo:

```bash
python scripts/import_projects.py --repo ../365-projects   # reads the project's README, top-level README table and git history
python scripts/shoot.py --repo ../365-projects 016         # needs: pip install playwright pillow && playwright install chromium, plus the projects repo's dependencies
python scripts/build_data.py
python -m pytest -q
git add -A && git commit -m "Add project 16" && git push
```

A project only counts as built once its folder in the projects repo has a README and a commit. If the importer
complains, fix the project's README in the projects repo rather than editing `data/built.json`.

## Rules for editing

* **Relative paths only.** The site must work at the root, under a sub-path and on a custom domain.
* `365projects/challenge-data.js` and `data/built.json` are generated. Change the inputs, then regenerate.
* No external requests from the pages (fonts are self-hosted, no analytics, no trackers). The one planned exception
  is the stlite CDN on the app pages described in `docs/BROWSER_APPS.md`.
* Reuse the tokens in `assets/site.css`. The look is a ledger-paper theme with eight section colours. The site is
  light only at the moment.
* Keep it accessible: visible keyboard focus, real buttons and links, `aria-live` for status text, reduced motion
  respected, text contrast kept. The gallery must be fully usable with the keyboard.
* Check any UI change in a real browser at 1280 px and 400 px wide before pushing (Playwright is fine). Look at it,
  do not only run the tests.
* Small commits with plain messages in the existing style, for example `Add project 16` or `Fix date format in the
  detail dialog`. Leave Claude Code's default co-author trailer on.

## Backlog, in priority order

1. **Browser apps.** Each built project opens at `https://varad-patel.github.io/365projects/N/` (N = 1, 2, 3, no
   zero padding) as a working app that runs entirely in the visitor's browser. Full plan, verified findings and
   acceptance checks are in `docs/BROWSER_APPS.md`.
2. **Gallery links.** Clicking a built project goes to its app page. The detail dialog's content (question, data,
   limits, finding, build date) moves into an "About this project" panel on that page.
3. **New projects.** Build projects 16 onward in the projects repo (see its `CLAUDE.md`), then add each one here
   with the commands above. Each new project must be browser-ready from day one (rule 9 in the projects repo's
   `docs/PROJECT_GUIDE.md`).
4. **Optional.** A custom domain such as `varad.me` (free for a year with the GitHub Student Developer Pack through
   Namecheap): add a `CNAME` file containing the domain, set it under Settings, Pages, Custom domain, and point four
   `A` records for `@` at 185.199.108.153, 185.199.109.153, 185.199.110.153 and 185.199.111.153 plus a `www`
   `CNAME` to `varad-patel.github.io`.

## Notes for cloud sessions

If Claude is running in a cloud session and not on a local machine: the Claude GitHub app must be installed on the
`varad-patel` organization (and on the `NotNeverMe` account for the projects repo), and a session can only push to
repositories attached to it. Treat a 403 or 407 from the proxy as an organisation policy decision and do not route
around it; stop and tell the user what was blocked.
