# Day 119: Belief Updater

Enter a claim and a prior, add evidence items one by one, and watch your confidence update with a saved history.

Live at https://varad-patel.github.io/365projects/119/ (part of [365 projects in 365 days](https://varad-patel.github.io/365projects/), section "Knowledge, Logic and Uncertainty").

| | |
|---|---|
| Question | How should a belief move as evidence arrives one piece at a time, and what goes wrong when the pieces are not independent? |
| One finding | With a 1% prior, one positive medical test gives 7.8% and a second gives 41.2%, but if the second test only repeats the first, counting its likelihood ratio again makes the belief more than five times what the evidence supports. |
| Main limit | The arithmetic is exact, but the prior and every likelihood ratio are the visitor's judgements, and the tool cannot measure how dependent the pieces of evidence really are. |
| PPE concept | Bayesian epistemology |
| Skills | Sequential Bayesian updating |
| Data | None. Everything is computed in the browser. |

## Files

* `index.html`: the page, including the write-up (the idea, how it works, what it cannot tell you, extensions).
* `logic.js`: the model, with no DOM code, so it can be tested on its own.
* `app.js`: the interface, built on the shared kit in `../kit/`.
* `logic.test.mjs`: tests for the model. Run them from the repository root with `node --test 365projects/119/logic.test.mjs`.

This file is generated by `scripts/build_data.py` from `meta.json` and `data/challenge.tsv`.
