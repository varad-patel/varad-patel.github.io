# Day 13: Fallacy Detector

Paste an argument and get possible fallacies flagged with confidence scores and a plain explanation of each, next to the detector's own measured error rate.

Live at https://varad-patel.github.io/365projects/13/ (part of [365 projects in 365 days](https://varad-patel.github.io/365projects/), section "Philosophy × Data").

| | |
|---|---|
| Question | Can a classifier that reads only the words of an argument tell which fallacy it commits, and how often is it wrong? |
| One finding | On 1,297 labelled arguments it had not seen, the detector named the right label 50% of the time, against 31% for always guessing the commonest label. |
| Main limit | It reads wording and not reasoning, so its top answer is wrong about half the time and it cannot see anything that depends on context. |
| PPE concept | Informal logic |
| Skills | Text classification, open labelled data |
| Data | Argotario (UKP Lab, TU Darmstadt) |

## Files

* `index.html`: the page, including the write-up (the idea, how it works, what it cannot tell you, extensions).
* `logic.js`: the model, with no DOM code, so it can be tested on its own.
* `app.js`: the interface, built on the shared kit in `../kit/`.
* `logic.test.mjs`: tests for the model. Run them from the repository root with `node --test 365projects/13/logic.test.mjs`.

This file is generated by `scripts/build_data.py` from `meta.json` and `data/challenge.tsv`.
