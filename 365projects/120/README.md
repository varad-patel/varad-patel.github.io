# Day 120: Bayesian Event Forecaster

Enter an event, pick a reference class and update as you add news, then see how the forecast compared with what happened.

Live at https://varad-patel.github.io/365projects/120/ (part of [365 projects in 365 days](https://varad-patel.github.io/365projects/), section "Knowledge, Logic and Uncertainty").

| | |
|---|---|
| Question | How far does the base rate of a well-chosen reference class get a forecast before any news arrives, and how do the forecasts score once the outcomes are known? |
| One finding | Forecasting each of the 161 first orbital attempts of a new rocket type from 2000 to 2025 with only the base rate known the day before, 54.0% for new families and 82.5% for new versions, scores 0.173 on the Brier score, against 0.197 with one rate for all and 0.25 for always saying 50%. |
| Main limit | The choice of reference class and the strength of each piece of news are judgements, and GCAT's grouping of rockets into families is one expert's. |
| PPE concept | Forecasting |
| Skills | Bayesian updating |
| Data | GCAT (J. McDowell) |

## Files

* `index.html`: the page, including the write-up (the idea, how it works, what it cannot tell you, extensions).

* `app.js`: the interface, built on the shared kit in `../kit/`.
* `logic.test.mjs`: tests for the model. Run them from the repository root with `node --test 365projects/120/logic.test.mjs`.
