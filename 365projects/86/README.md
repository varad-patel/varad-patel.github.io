# Day 86: Election Forecast Model

See a probabilistic forecast built from open polling data and change the polling-error assumptions yourself.

Live at https://varad-patel.github.io/365projects/86/ (part of [365 projects in 365 days](https://varad-patel.github.io/365projects/), section "Politics × Data").

| | |
|---|---|
| Question | How likely did the polls make each candidate's victory in 2016 and 2020, and what does the result say about those probabilities? |
| One finding | On election morning with the default assumptions the model gives Biden 93.9% in 2020 and Clinton 82.9% in 2016; its Brier scores of 0.037 and 0.075 would be matched or exceeded 60% and 11% of the time by a forecast exactly right about its own uncertainty, so neither year shows its probabilities were wrong. |
| Main limit | Two elections cannot establish how large or how correlated polling errors are, so the error settings that drive the probabilities remain assumptions. |
| PPE concept | Democratic uncertainty |
| Skills | Bayesian aggregation, Monte Carlo |
| Data | FiveThirtyEight polls (CC BY 4.0), Federal Election Commission, US Census Bureau, Certificates of ascertainment (National Archives) |

## Files

* `index.html`: the page, including the write-up (the idea, how it works, what it cannot tell you, extensions).
* `logic.js`: the model, with no DOM code, so it can be tested on its own.
* `app.js`: the interface, built on the shared kit in `../kit/`.
* `logic.test.mjs`: tests for the model. Run them from the repository root with `node --test 365projects/86/logic.test.mjs`.

This file is generated by `scripts/build_data.py` from `meta.json` and `data/challenge.tsv`.
