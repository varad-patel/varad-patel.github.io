# Day 88: Electoral College Simulator

Change state swings and see how often the popular-vote and electoral winners differ.

Live at https://varad-patel.github.io/365projects/88/ (part of [365 projects in 365 days](https://varad-patel.github.io/365projects/), section "Politics × Data").

| | |
|---|---|
| Question | How often does the candidate who wins the popular vote lose the electoral college, and how wide is the window in which that can happen? |
| One finding | From the 2020 result swung uniformly, Biden needed more than 51.95% of the two-party vote, a lead of 3.9 points, to win the electoral college, so anywhere from 50% to 51.68% the popular-vote winner loses (with a 269 tie up to 51.95%); with the default uncertainty that happens in 22% of simulated elections from the 2020 map and 12% from the 2024 map. |
| Main limit | How often an inversion happens depends almost entirely on the assumed size and pattern of the swings, which are the visitor's settings, not estimates. |
| PPE concept | Representation |
| Skills | Monte Carlo simulation |
| Data | Federal Election Commission, US Census Bureau, Certificates of ascertainment (National Archives), US House of Representatives, Office of the Historian |

## Files

* `index.html`: the page, including the write-up (the idea, how it works, what it cannot tell you, extensions).
* `logic.js`: the model, with no DOM code, so it can be tested on its own.
* `app.js`: the interface, built on the shared kit in `../kit/`.
* `logic.test.mjs`: tests for the model. Run them from the repository root with `node --test 365projects/88/logic.test.mjs`.

This file is generated by `scripts/build_data.py` from `meta.json` and `data/challenge.tsv`.
