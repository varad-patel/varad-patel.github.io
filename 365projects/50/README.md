# Day 50: Price War Simulator

Set up competing pricing bots and watch whether they undercut each other or settle into collusion.

Live at https://varad-patel.github.io/365projects/50/ (part of [365 projects in 365 days](https://varad-patel.github.io/365projects/), section "Economics × Data Science").

| | |
|---|---|
| Question | Do pricing bots that learn by trial and error undercut each other down to the competitive price, or do they settle on high prices and punish a price cut? |
| One finding | In ten simulated runs of two Q-learning bots (seeds 1 to 10) prices settle at 1.80 on average, between the one-shot Nash price of 1.473 and the joint-monopoly price of 1.925, a profit gain of 87% (58% to 98% by seed); a forced one-period price cut loses money in all ten and is answered with a lower price in nine. |
| Main limit | It is a simulation of two copies of one simple algorithm in an invented, unchanging market, taking about 1.8 million periods to learn, so it shows that collusion can be learned without being programmed, not that real pricing software does it or that it would be unlawful. |
| PPE concept | Competition policy |
| Skills | Reinforcement learning |
| Data | None. Everything is computed in the browser. |

## Files

* `index.html`: the page, including the write-up (the idea, how it works, what it cannot tell you, extensions).
* `logic.js`: the model, with no DOM code, so it can be tested on its own.
* `app.js`: the interface, built on the shared kit in `../kit/`.
* `logic.test.mjs`: tests for the model. Run them from the repository root with `node --test 365projects/50/logic.test.mjs`.

This file is generated by `scripts/build_data.py` from `meta.json` and `data/challenge.tsv`.
