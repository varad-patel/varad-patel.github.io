Gödel Numbering Encoder

Type a formula of arithmetic to turn it into a single whole number, or paste a number to turn it back into a formula. This is the trick that lets arithmetic talk about its own sentences.

One finding

Almost no number is a formula. Of the whole numbers from 1 to 1,000,000, only 781 are the code of any string of the 17 symbols, 17 of those are terms, and exactly three are well-formed formulas: 2,430 (0=0), 85,050 (0=S0) and 262,500 (S0=0). The seven-symbol sentence ∀x¬Sx=0, "zero is not the successor of anything", already needs a number 39 digits long.

The idea

In 1931 Kurt Gödel published a paper that undermined the hope, associated with David Hilbert, of a single system of axioms that would settle every question of mathematics and could be shown, by elementary reasoning, to be free of contradiction. The proof starts with a piece of bookkeeping. Give each symbol of a formal language a number. Then a formula, which is a row of symbols, can be packed into one number: raise the first prime to the code of the first symbol, the second prime to the code of the second, and multiply. Because every whole number factors into primes in exactly one way, the formula can always be unpacked again.

The point of the packing is what it does to statements about formulas. "This string is well formed", "this formula follows from those two by a rule of inference" and "this list of formulas is a proof" all become statements about numbers: a number has a certain pattern of prime exponents, or stands in a certain computable relation to other numbers. And statements about numbers are exactly what a formal theory of arithmetic can express. So a theory of arithmetic can, in its own language, describe its own formulas and proofs.

From there the first incompleteness theorem runs, in outline, as follows. Take a consistent formal system F whose axioms can be listed by a mechanical procedure and which proves the basic facts of arithmetic. Gödel showed there is a formula of arithmetic, Prov(x), that holds of a number exactly when it is the Gödel number of a formula provable in F. A further construction, the diagonal lemma, yields a sentence G for which F proves "G if and only if not Prov(the number of G)". Loosely, G says "I am not provable in F". If F proved G, the proof could be checked by arithmetic, so F would also prove Prov(the number of G), which contradicts G: F would be inconsistent. So F does not prove G, which is what G says. Gödel showed that F does not prove the negation of G either, under a slightly stronger assumption than consistency; in 1936 J. Barkley Rosser, using a modified sentence, showed that plain consistency is enough. Either way F leaves a sentence of its own language undecided.

This is the Liar of day 21 with "false" replaced by "unprovable", and the replacement turns a paradox into a theorem. The same move, treating descriptions of a system as data inside the system, is what Alan Turing used five years later to define computation, and it is why a computer can store a program as a number. This page carries out only the first step: the numbering, and the simplest syntactic check on what a number encodes.

How it works

The language

The language has 17 symbols. Each has a code from 1 to 17.

There are no digits other than 0. The number two is written SS0, "the successor of the successor of zero". As a convenience a typed numeral up to 60 is expanded into that form before anything else happens. Spaces are ignored and are not part of the string.

A string of symbols is a well-formed formula if it can be built by these rules, where { } means "repeated any number of times" and [ ] means "optional":

variable ::= ( x | y | z ) { ′ }
factor   ::= 0 | variable | S factor | ( term )
product  ::= factor { × factor }
term     ::= product { + product }
unit     ::= term = term | ¬ unit | ( formula )
           | ∀ variable unit | ∃ variable unit
conj     ::= unit { ∧ unit }
disj     ::= conj { ∨ conj }
formula  ::= disj [ → formula ]

In words: S applies to the next factor only; × binds tighter than +; ¬ and the quantifiers apply to the next unit only; ∧ binds tighter than ∨, which binds tighter than →; repeated +, ×, ∧ and ∨ group to the left and repeated → groups to the right. A term names a number; a formula says something. Brackets override the grouping. Because the order of operations is written into the rules themselves, a string can be built in at most one way: a test counts the ways of building every string of up to four symbols, and of thousands of longer ones, and never finds two.

Encoding

Let the symbols of the string have codes c1, c2, …, ck and let pi be the i-th prime. The Gödel number of the string is

g = 2c1 × 3c2 × 5c3 × … × pkck

For 0=0 the codes are 1, 5, 1, so g = 21 × 35 × 51 = 2 × 243 × 5 = 2,430. The arithmetic is done with exact integers of any length, so nothing is rounded. Every string gets a number, whether or not it is well formed: the numbering is about spelling, not meaning.

Decoding

Given a whole number, divide by 2 as many times as it will go; the count is the first code. Do the same with 3 for the second code, with 5 for the third, and continue until nothing is left but 1. Three things can go wrong, and each is reported exactly:

  • A prime is skipped. If the next prime does not divide what remains, and what remains is not 1, some position would have no symbol. 10 = 2 × 5 skips 3, so it is not the code of any string.
  • An unknown code. If a prime divides the number more than 17 times, the position would hold a symbol that does not exist. 218 = 262,144 is an example.
  • A string, but not a formula. 7,776 = 25 × 35 decodes without trouble to "==", which the grammar cannot build.

The fundamental theorem of arithmetic says every whole number above 1 is a product of primes in exactly one way. That is why two different strings can never share a number and why decoding always recovers what was encoded. The numbers 0 and 1 are special cases: 0 has no factorisation, and 1, the empty product, would be the code of the empty string.

The syntax check

The check is a recursive-descent parser with one function for each line of the grammar. It reads the codes from left to right and either builds a tree or stops at the first symbol that cannot continue any rule, reporting that position and what was needed there. An opening bracket is the one place where it has to try twice: "(" may start a bracketed formula, as in (x=y∧y=z), or a bracketed term, as in (x+y)=z, so it tries the formula first and falls back to the term. If the string is not a formula the parser is run again to see whether it is a term.

For a well-formed formula the page also lists its free variables (those not governed by a quantifier), writes it out with every bracket restored, and, in the one case where truth can be settled by calculation, a formula with no variables at all, says whether it is true.

Counting codes

The count at the end of the tool decodes every number from 1 up to the limit you choose and classifies what comes out. It is the direct way to see how thinly formulas are spread among the numbers.

What this cannot tell you

  • That arithmetic is incomplete. The page does the numbering and nothing more. It has no axioms, no rules of inference, no notion of proof, no provability formula and no diagonal sentence. The sketch above is a summary of Gödel's argument, not something the tool establishes.
  • Whether a formula is true or provable. Well formed, true and provable are three different properties. S0=0 is well formed and false. The page checks truth only for formulas with no variables, where it is a matter of calculation; for sentences with quantifiers no mechanical method can decide truth in general, a result closely related to Gödel's.
  • Anything about the numbers themselves. The code table is a convention. Gödel's own table was different (he gave his basic signs the odd numbers from 1 to 13), and any mechanical one-to-one coding would serve. A particular Gödel number means nothing apart from the table that produced it.
  • What the real undecidable sentence looks like. Prime-power coding is wildly wasteful, and the page stops at 200 symbols and 10,000 digits. Gödel's sentence written in this language would contain the numeral for a Gödel number, and a numeral for n is n copies of S. It could not be displayed here or anywhere else.
  • What counts as well formed in general. The grammar here is one choice among many. It lets brackets be left out and fixes the reading by precedence, and that each string then has only one reading has been checked by exhaustive test, not proved. Many textbooks instead require every bracket, which gives a simpler grammar for which "each formula can be read in only one way" is a standard theorem.
  • The factors of an arbitrary number. The decoder is not a general factoriser. For a number that is not a code it stops at the first missing prime, and it names the next prime factor only when that factor is below 110,000 or the remainder is small enough to test directly.

Improvements and extensions

  • Number a sequence of formulas the same way, 2 to the first formula's number times 3 to the second's and so on, so that a whole proof becomes one number.
  • Add the axioms of a weak arithmetic such as Robinson's Q and a proof checker, so that "this number encodes a proof of that formula" becomes something the page can test.
  • Implement substitution as an operation on Gödel numbers and build the diagonal sentence step by step, with numerals kept symbolic instead of written out.
  • Offer other codings, such as reading the codes as digits in base 18, and compare how fast the numbers grow.
  • Draw the syntax tree the parser builds, and show the bound and free occurrences of each variable on it.
  • Add bounded quantifiers (for all x below a term) and evaluate them, to show the class of formulas whose truth can still be settled by calculation.
