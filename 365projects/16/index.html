Argument Map Builder

Draw an argument as claims and the reasons given for them. Then take premises away, one at a time or several together, and see which ones the conclusion cannot do without.

One finding

The congestion-charge example gives two separate reasons for its conclusion, which rest on seven premises in all. Six of the seven can each be removed alone and the conclusion still stands. The seventh, "the charge can be enforced cheaply and reliably", sits under both reasons, so removing it alone brings the conclusion down. Every other way of defeating the argument needs two premises to go together, and there are nine such pairs.

The idea

An argument is not a list of sentences that happen to end in "therefore". Its premises do different jobs. Some only work as a team: "all humans are mortal" says nothing about Socrates until "Socrates is a human" joins it. Others are separate reasons for the same conclusion, each of which would do by itself. Stephen Thomas called the first kind linked and, following Monroe Beardsley, the second kind convergent. An argument map draws that difference: linked premises are joined before they reach the claim, and independent reasons arrive by separate arrows.

The habit of drawing arguments is older than the vocabulary. John Henry Wigmore charted the evidence in trials in 1913 so that a lawyer could see which inferences a verdict hung on. Beardsley brought diagrams into logic teaching in 1950, and Stephen Toulmin's 1958 layout added the idea that the step from data to claim rests on a further, often unspoken, statement that licenses it, which he called the warrant. What they share is the thought that the shape of the support matters as much as its content. A conclusion with three independent reasons survives the loss of one. A conclusion at the end of a single chain is only as secure as the weakest link in it.

This matters outside a logic class because public arguments rarely show their structure. A case for a policy usually offers several attractive reasons and leaves the reader to assume they are independent. Often they are not: they share a premise, and the whole case turns on it. Arguments also leave premises out. "A higher minimum wage makes workers dearer to employ, so it will cost jobs" needs the further claim that employers respond by employing fewer people, which is the very thing economists have disputed since Card and Krueger compared fast-food restaurants on either side of a state border in the 1990s. A map does not settle that dispute. It shows that this is where the dispute has to be.

The tool turns the picture into something you can test. Remove a premise and it recomputes which claims still have support. Engineers will recognise the method: it is the calculation used to find single points of failure in a fault tree, applied to reasons in place of components.

How it works

The map

A map is a set of claims and a set of reasons. A reason belongs to one claim and names one or more other claims as its premises. A claim may have several reasons. A claim with no reason is a premise of the map: something it asserts and does not argue for. One claim is marked as the main conclusion. Claims that have reasons and are also used in reasons are sub-conclusions, so arguments can be several steps deep and a claim can be used in more than one place.

What stands

Each premise is either in play or removed. Whether any other claim stands is then fixed by one rule:

a premise stands if it is in play
a claim with reasons R1, …, Rk stands if
(all of R1 stand) or … or (all of Rk stand)

Inside a reason the members are joined by "and"; between reasons the connective is "or". The tool evaluates the rule from the premises upward, visiting each claim once and remembering the answer, so a claim used in several places is computed a single time. A reason is drawn solid while all its members stand and broken once one of them has gone.

Critical, redundant and idle premises

For every premise in play the tool removes it, re-evaluates the map and puts it back. If the main conclusion falls, the premise is critical. If the conclusion survives, the premise is redundant in the engineering sense: it belongs to a line of support, but a line that does not need it is still whole. A premise is idle if no smallest sufficient set of premises contains it, which happens when it appears only in a reason that another reason already makes unnecessary. A premise the conclusion does not rest on anywhere is marked as unused. All of this is relative to the premises currently removed, so the labels change as you take things away.

Lines of support and smallest objections

The rule above makes the conclusion a Boolean function of the premises. The tool rewrites it in two minimal forms. Writing S(c) for the family of smallest sets of premises that are enough for c:

S(p) = { {p} } for a premise p
S(c) = min ⋃i { A1 ∪ … ∪ An : Aj ∈ S(mj) for each member mj of Ri }

where "min" discards any set that contains another set in the family. Each surviving set is one line of support. Swapping the roles of "and" and "or" gives the family O(c) of smallest objections: sets of premises whose removal leaves no reason for c whole.

O(p) = { {p} }    O(c) = min { B1 ∪ … ∪ Bk : Bi ∈ ⋃j O(mij) }

Reliability engineers call these minimal path sets and minimal cut sets. A premise is critical exactly when it is in every line of support, which is the same as being an objection of size one; the tests check both statements against a brute-force search over every combination of removals on random maps. When some premises are already removed, the tool subtracts them from each objection and keeps the smallest remainders, which answers "what else would have to go?". Once the conclusion has fallen it does the mirror-image calculation and lists the smallest sets to put back. The number of sets can grow exponentially, so the lists stop at 2,000; the map and the labels do not depend on them and stay exact.

Refusing circles

Support must run one way. After any edit that adds or changes a reason, and for every imported file, the tool searches the graph depth-first for a claim that can be reached from itself. If it finds one, the edit is refused and the loop is spelled out: "A rests on B rests on A". A circular argument gives no independent support to anything in the circle, and the rule for what stands would have no single answer on it.

Drawing

Each claim is placed one layer below the lowest claim it supports, so every arrow points up and the premises hang at the bottom of their branches. A premise can then sit several layers below a claim it supports. Its line is given a narrow lane of its own through each layer in between, placed like a box, so that no line runs behind a box; lines bend only in the gaps between layers, where they may cross each other. Claims and lanes are ordered within a layer by a depth-first walk from the top. Horizontal positions come from six rounds of pulling each one towards the average position of what it supports, then of what supports it, each time restoring a minimum gap by the least-squares method of pooling neighbours that would collide. Text is measured in the page font and wrapped to the box. On a narrow screen the drawing scrolls sideways, and the same map is written out as an indented list beneath it.

Saving

The map, and which of its premises are removed, are kept in this browser's local storage and nothing is sent anywhere. "Export JSON" writes the title, the claims, the reasons and the main conclusion to a file, without the removals; "Import JSON" reads one back, renumbers it and refuses anything unsound. "Undo" takes back the last change, whether it was an edit or a removal, up to 60 steps.

What this cannot tell you

  • Whether the premises are true. A premise is "in play" because you left it switched on. The map of a case built on falsehoods stands exactly as firmly as the map of a sound one.
  • Whether the reasons are any good. The tool takes it on trust that a reason, with all its premises in place, is enough for the claim it points to. It does not check validity or strength. Draw an arrow from "the moon is made of rock" to "taxes should rise" and it will report that the conclusion stands.
  • How much support there is. Everything here is all or nothing. Real convergent reasons add up by degrees, and a chain of five plausible premises can be less credible than any one of them. "Stands" means "has an unbroken line of support in this map", not "is probably true".
  • What an opponent would say. The map holds only support. There are no counter-arguments, rebuttals or exceptions in it, and the "objections" it lists are removals of premises, not reasons for doubting them.
  • Whether the map is the argument. Deciding that two premises are linked and not convergent is a judgement, and careful readers map the same paragraph differently. Unstated premises appear only if you add them, so an argument with its awkward assumption left out will look stronger than it is.
  • Which premises matter most in general. "Critical" and "redundant" describe this map in its current state. Add a second reason and a critical premise becomes redundant; remove a line and redundant premises become critical. A redundant premise is not an unimportant one.

Improvements and extensions

  • Add objections and rebuttals as a second kind of edge and decide what stands with the acceptability semantics of Dung's abstract argumentation frameworks.
  • Let each premise carry a probability and report the chance that the conclusion keeps a whole line of support, the calculation used for system reliability, with an explicit statement of the independence it assumes.
  • Offer argumentation schemes with their critical questions, so that choosing "argument from expert opinion" prompts for the premises that scheme usually leaves unstated.
  • Let claims be dragged into place, and reorder each layer to keep the number of crossing lines as low as it can be.
  • Encode a map in the page address so that it can be shared as a link without a file.
  • Draft a map from pasted prose by splitting on indicator words such as "because", "since" and "therefore", for the user to correct.
