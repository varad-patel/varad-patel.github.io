# Day 60: Stable Matching Marketplace

Enter preferences for candidates and employers and get a stable matching with an explanation.

Live at https://varad-patel.github.io/365projects/60/ (part of [365 projects in 365 days](https://varad-patel.github.io/365projects/), section "Economics × Data Science").

| | |
|---|---|
| Question | How can candidates and employers be matched so that no candidate and employer would both rather have each other, and does it matter who proposes? |
| One finding | In the opening market of six candidates and five positions, three candidates get their first choice when candidates propose and one when employers do; with candidates proposing, none of the 84 false lists a candidate could send helps that candidate, while Acme gains by leaving Chloe off its list. |
| Main limit | Stability says only that no pair wants to break away, on the lists as reported: it does not make the matching fair or the lists true, and it ignores ties, couples and pay. |
| PPE concept | Market design |
| Skills | Gale-Shapley algorithm |
| Data | None. Everything is computed in the browser. |

## Files

* `index.html`: the page, including the write-up (the idea, how it works, what it cannot tell you, extensions).
* `logic.js`: the model, with no DOM code, so it can be tested on its own.
* `app.js`: the interface, built on the shared kit in `../kit/`.
* `logic.test.mjs`: tests for the model. Run them from the repository root with `node --test 365projects/60/logic.test.mjs`.

This file is generated by `scripts/build_data.py` from `meta.json` and `data/challenge.tsv`.
