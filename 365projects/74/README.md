# Day 74: Central Bank Simulator

Play central banker: set rates each quarter and see inflation and output respond, with a score.

Live at https://varad-patel.github.io/365projects/74/ (part of [365 projects in 365 days](https://varad-patel.github.io/365projects/), section "Economics × Finance").

| | |
|---|---|
| Question | How well can you steer inflation and output with one interest rate when you only know what has already happened? |
| One finding | On the opening shocks, holding the rate at 6% scores 6.47, the best anyone could expect from last quarter's figures 2.07 and the public's rule with this quarter's figures 0.88 (3.34, 1.62 and 0.47 over 2,000 games); in the lab, Taylor's rule meets a one-point monetary policy shock with a rate only 0.34 points higher, and a response to inflation of 0.95 leaves the model without a unique equilibrium. |
| Main limit | The basic New Keynesian model has no memory and acts within the quarter, and its public never learns, so the game understates the cost of falling behind. |
| PPE concept | Monetary policy |
| Skills | New Keynesian model |
| Data | None. Everything is computed in the browser. |

## Files

* `index.html`: the page, including the write-up (the idea, how it works, what it cannot tell you, extensions).
* `logic.js`: the model, with no DOM code, so it can be tested on its own.
* `app.js`: the interface, built on the shared kit in `../kit/`.
* `logic.test.mjs`: tests for the model. Run them from the repository root with `node --test 365projects/74/logic.test.mjs`.

This file is generated by `scripts/build_data.py` from `meta.json` and `data/challenge.tsv`.
